# UI Specs

All specs in this file apply to the static browser client in `site/` unless a spec names another artifact. "The endpoint" means the value of `window.PHENO_API_ENDPOINT` defined by `site/config.js`.

## Observability

- [x] **UI-UI-023**: The browser client shall write every log event through a single `log(level, event, fields)` helper that emits one JSON object per event, containing `level`, `event`, and the event's fields, via `console.info`, `console.warn`, or `console.error` according to the level.
- [x] **UI-UI-024**: When the browser client sends a `POST /predict` request, the system shall emit an `INFO` log event containing the input source (`upload` or `sample`), the filename, and the file size in bytes.
- [x] **UI-UI-025**: When a `POST /predict` request returns a non-2xx HTTP status, the browser client shall emit an `ERROR` log event containing the HTTP status code, the `error` code from the response body (or null if absent), and the `detail` field (or null if absent).
- [x] **UI-UI-026**: When a network error, a client-side timeout, or an unexpected exception occurs during a live prediction, the browser client shall emit an `ERROR` log event containing the error message and the stack trace.
- [x] **UI-UI-044**: If an uploaded file fails browser-side validation, then the browser client shall emit a `WARN` log event containing the filename and the list of validation errors.
- [x] **UI-UI-045**: When a precomputed sample result is rendered, the browser client shall emit an `INFO` log event containing the sample label, the predicted phenotype, and the confidence score.
- [x] **UI-UI-046**: When a live prediction result is rendered, the browser client shall emit an `INFO` log event containing the predicted phenotype, the confidence score, and the number of markers.
- [x] **UI-UI-047**: If a precomputed sample result cannot be fetched or parsed, then the browser client shall emit a `WARN` log event containing the sample label and the error message.
- [x] **UI-UI-048**: If the endpoint is empty or `config.js` failed to load, then the browser client shall emit an `ERROR` log event on page load stating that the API endpoint is not configured.
- [x] **UI-UI-049**: The browser client shall emit no log event for the outcome of the `GET /health` warm-up request.

## Warm-up

- [x] **UI-UI-027**: When the page loads and the endpoint is non-empty, the browser client shall send exactly one `GET {endpoint}/health` request, and shall not wait for its response before enabling user interaction.
- [x] **UI-UI-028**: When the `GET /health` warm-up request completes, fails, or errors, the browser client shall make no change to the page and shall not retry the request.
- [x] **UI-UI-029**: If the endpoint is empty or `config.js` failed to load, then the browser client shall not send the `GET /health` warm-up request.

## Input

- [x] **UI-UI-001**: The browser client shall present a file input that accepts `.vcf` files.
- [x] **UI-UI-003**: If the user-uploaded file's name does not end in `.vcf`, compared case-insensitively, then the browser client shall display an inline error message next to the upload control and shall not send the file for prediction.
- [x] **UI-UI-004**: If the user-uploaded file exceeds 4 MiB (4,194,304 bytes), then the browser client shall display an inline error message next to the upload control and shall not send the file for prediction.
- [x] **UI-UI-005**: If the user-uploaded VCF has no `#CHROM` header line, or its `#CHROM` header line has a number of columns after `FORMAT` other than exactly one, then the browser client shall display an inline error message next to the upload control and shall not send the file for prediction.

## Prediction Request

- [x] **UI-UI-008**: When the user clicks Run Prediction with an uploaded file that passes browser-side validation, the browser client shall send `POST {endpoint}/predict` with header `Content-Type: application/json` and body `{"vcf": <file contents as UTF-8 text>}`, and no other body fields.
- [x] **UI-UI-038**: When the user clicks Run Prediction, the browser client shall submit the uploaded file only, regardless of which sample radio option is selected.
- [x] **UI-UI-051**: While no file is chosen in the upload control, the browser client shall disable the Run Prediction button, regardless of the sample selection.
- [x] **UI-UI-030**: If the user clicks Run Prediction while the endpoint is empty or `config.js` failed to load, then the browser client shall display "The prediction service is not configured." and shall send no request.
- [x] **UI-UI-009**: While a live prediction request is in progress for the current action, the browser client shall display a loading indicator and disable the Run Prediction button.
- [x] **UI-UI-010**: If a live prediction request fails with a network error, receives no response within 35 seconds (after which the client aborts it), or returns an error response not mapped by `UI-UI-015`, `UI-UI-035`, or `UI-UI-036`, then the browser client shall display "The prediction request failed — please try again." and re-enable the Run Prediction button.
- [x] **UI-UI-015**: When a live prediction request returns an error response in the format defined by `DEPLOY-BE-022` (`{"error": <code>, "detail": <message>}`), the browser client shall map the `error` code to a human-readable message: `MODEL_UNAVAILABLE` → "The prediction service is starting up or unavailable — please try again in a moment."; `INVALID_VCF` → "The uploaded VCF could not be processed (multi-sample file, malformed format, or no usable variants)."; `INVALID_INPUT` → "The request was rejected as malformed — please reload and try again."; `INFERENCE_FAILED` / `INTERNAL_ERROR` → "The prediction service encountered an error — please try again or contact support." Unknown codes shall fall through to the `UI-UI-010` message.
- [x] **UI-UI-035**: When a live prediction request returns HTTP 503 or 504 with a body that is not in the `{"error", "detail"}` format, the browser client shall display "The prediction service is starting up or unavailable — please try again in a moment."
- [x] **UI-UI-036**: When a live prediction request returns HTTP 429, the browser client shall display "The demo is busy right now — please try again in a few seconds."
- [x] **UI-UI-059**: When the browser client displays an error message in the results area, it shall hide any previously rendered prediction result.
- [x] **UI-UI-034**: When a sample selection or Run Prediction supersedes an earlier pending sample selection or Run Prediction, the browser client shall immediately set the loading indicator and Run Prediction button to the new action's state.
- [x] **UI-UI-052**: When a sample selection or Run Prediction supersedes an earlier pending one, the browser client shall cancel the superseded action's in-flight `fetch` through its `AbortController`.
- [x] **UI-UI-053**: If a response arrives for a superseded sample selection or Run Prediction, then the browser client shall discard it without rendering it.

## Sample Input

- [x] **UI-UI-016**: When `samples/manifest.json` loads on page load and contains at least one entry, the browser client shall display a "Don't have a file? Try a sample" `<details>` section above the upload control, open by default.
- [x] **UI-UI-017**: If `samples/manifest.json` fails to load, fails to parse, or contains no entries, then the browser client shall hide the "Try a sample" section and display no error.
- [x] **UI-UI-018**: The "Try a sample" section shall present a radio group whose first option is "None — use uploaded file", followed by one option per `samples/manifest.json` entry, in manifest order, labelled with the entry's `label`.
- [x] **UI-UI-019**: On page load, the sample radio group shall have "None — use uploaded file" selected.
- [x] **UI-UI-031**: When the user selects a sample option, the browser client shall fetch that entry's `result` JSON from `samples/` and render it as the prediction result, sending no request to the endpoint.
- [x] **UI-UI-033**: If a selected sample's `result` JSON cannot be fetched or does not parse and the endpoint is non-empty, then the browser client shall fetch that sample's `vcf` file from `samples/` and send it as a live prediction per `UI-UI-008`.
- [x] **UI-UI-054**: If a selected sample's `result` JSON cannot be fetched or does not parse and the endpoint is empty or `config.js` failed to load, then the browser client shall display "The prediction service is not configured." and shall send no request.
- [x] **UI-UI-022**: When a sample VCF is sent as a live prediction, the browser client shall skip browser-side validation (extension, size, and sample-count checks).
- [x] **UI-UI-039**: When the user selects "None — use uploaded file", the browser client shall leave the results panel unchanged and shall not supersede, cancel, or discard any pending sample fetch or live prediction.

## Results Display

- [x] **UI-UI-011**: When a prediction result is rendered, the browser client shall display the predicted ancestral population label, the confidence score as a percentage rounded to the nearest whole number with a progress bar, and the top contributing markers.
- [x] **UI-UI-032**: When a prediction result is rendered, the browser client shall display a source line reading "Precomputed result for <sample label>" for a precomputed sample result, or "Live prediction" for a result returned by `POST /predict`.
- [x] **UI-UI-012**: The browser client shall display the top contributing markers (as defined in PRED-DATA-002) in a ranked table showing rank, variant ID, chromosome, position, and SHAP contribution value.
- [x] **UI-UI-014**: The browser client shall display the top contributing markers as an inline-SVG horizontal bar chart with one bar per marker, sorted by absolute SHAP contribution value descending from top to bottom, each bar labelled with its variant ID.
- [x] **UI-UI-037**: In the marker bar chart, every bar shall start at a shared zero axis, extending to the right for a positive SHAP contribution and to the left for a negative one, with length proportional to the absolute value and scaled so that the bar with the largest absolute value in the chart fills its half of the chart width.

## Sample Results and Site Delivery

- [x] **UI-UI-040**: `bin/06_precompute_samples.sh` shall send each file in `samples/` matching `sample_snp_[0-9]*.vcf` to `POST {PHENO_API_ENDPOINT}/predict` and write the response body unchanged to `samples/sample_snp_N.result.json`, where N is the file's numeric suffix.
- [x] **UI-UI-058**: If any response to `bin/06_precompute_samples.sh` is not HTTP 200, or `PHENO_API_ENDPOINT` is unset, then the script shall exit non-zero without creating or modifying any `samples/sample_snp_N.result.json` file.
- [x] **UI-UI-057**: Every committed `samples/sample_snp_N.result.json` file shall carry the same `model_artifact_version` value.
- [x] **UI-UI-041**: When the `deploy` job in `.github/workflows/ci.yaml` runs, it shall write `samples/manifest.json` into the site containing one entry `{"label": "Sample SNP N", "vcf": "sample_snp_N.vcf", "result": "sample_snp_N.result.json"}` per repo `samples/` file matching `sample_snp_[0-9]*.vcf`, ordered by N ascending, and copy each listed VCF and result file into the site's `samples/` directory.
- [x] **UI-UI-055**: If any repo `samples/` file matching `sample_snp_[0-9]*.vcf` has no `sample_snp_N.result.json` beside it, then the `deploy` job in `.github/workflows/ci.yaml` shall fail without publishing the site.
- [x] **UI-UI-042**: When the `deploy` job in `.github/workflows/ci.yaml` runs, it shall write `config.js` into the site defining `window.PHENO_API_ENDPOINT` as the value of the GitHub repository variable `PHENO_API_ENDPOINT`.
- [x] **UI-UI-043**: The `deploy` job in `.github/workflows/ci.yaml` shall publish the assembled site to GitHub Pages using `actions/upload-pages-artifact` and `actions/deploy-pages`.
- [x] **UI-UI-056**: The `deploy` job in `.github/workflows/ci.yaml` shall declare `needs: test` and shall run only for pushes to `main` and manual (`workflow_dispatch`) runs on `main`, never for pull requests.
- [x] **UI-UI-050**: `bin/05_ui.sh` shall assemble the site as `UI-UI-041` and `UI-UI-042` describe, taking `PHENO_API_ENDPOINT` from its environment, and serve it with `python -m http.server 8000`.
